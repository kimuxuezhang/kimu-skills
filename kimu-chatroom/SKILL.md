# Kimu 定向聊天室

根据话题推荐或接受用户指定的专家，用多个独立角色展开讨论，并由主持人总结洞察、分歧和可执行建议。

这是 Kimu 工具箱的叶子模块，可由 `$kimu` 主入口路由，也可由用户直接调用。

## 聊天室边界

人物确认后，聊天室持续进行，直到用户明确结束。每次专家发言与主持人总结构成一轮讨论，用于沉淀当前结论，不关闭聊天室。

聊天室进行中，用户的普通后续输入默认交给同一组专家继续讨论。用户说「结束聊天室」「退出聊天室」、调用 `$kimu` 或明确要求回到主入口时，结束聊天室。

后续讨论复用已确认的人物、原话题和主持人总结，只围绕用户的新问题展开下一轮，不重新推荐人物。

## 工作流程

### 第一步：检测模式

**情况 C：活动聊天室中的后续输入**

- 触发方式：当前对话存在标记为「聊天室仍在进行」的上一轮聊天室，用户继续输入，且没有明确结束聊天室。
- 前提：能读取到上一轮人物、话题和主持人总结。
- 动作：直接进入第三步，沿用上一轮人物；将用户的新问题作为本轮讨论焦点。

**情况 D：结束聊天室**

- 触发方式：用户说「结束聊天室」「退出聊天室」、调用 `$kimu` 或明确要求回到主入口。
- 动作：结束聊天室，不再调用专家；用户调用了 `$kimu` 时，将当前结论交给主入口继续路由。

**情况 A：用户指定了人物**

- 格式：`$kimu-chatroom [人物1] [人物2] [人物3]`
- 示例：`$kimu-chatroom 查理·芒格 丹尼尔·卡尼曼 雷·达里奥`
- 动作：直接进入第三步。
- 用户明确点名的在世人物属于用户选择，不把他包装成系统推荐；需要调整名单时，仍按第二步的推荐规则补人。

**情况 B：用户未指定人物**

- 触发方式：用户调用 `$kimu-chatroom` 或使用其他触发词，但没有指定人物。
- 动作：进入第二步。

### 第二步：推荐人物（仅情况 B）

分析话题，推荐 3–5 位专家：

```text
🎯 根据话题「{话题总结}」，推荐以下专家：

1. {人物1}：{核心观点一句话}
2. {人物2}：{核心观点一句话}
3. {人物3}：{核心观点一句话}

确认后启动聊天室。
```

停在这里，等待用户回复「确认」「开始」或调整人选，不继续生成对话。

#### 推荐人物规则

人物在聊天室里代表一个可检验的理论框架。先选理论，再选理论的代表人物。推荐的目标是让多个框架处理同一个问题，形成分工、分歧或校正，推动用户做出判断。

先把话题拆成缺失的判断变量，再找覆盖这些变量的理论。人物的知名度、表达能力和个人经历不构成起点。

##### 理论筛选

每个候选理论都要先通过以下筛选：

1. **命题清楚**：能说出核心命题、适用边界和判断方法。
2. **经受时间检验**：经历过长期使用、批评、反驳和修正，价值不依赖一时流行。
3. **可独立验证**：理论的价值能通过原著、研究、案例或长期实践检验，不依赖提出者持续讲述自己的成功。
4. **能够处理当前变量**：理论能让用户区分具体选择，并覆盖当前讨论中其他理论没有覆盖的变量。
5. **材料足够**：有可靠的一手文本与足够的解释材料，能够忠实还原方法，不把零散名言拼成虚构观点。

满足这些条件的理论，通常来自已经完成其思想与实践检验的历史人物。已故和在世不是筛选条件，也不设置人数比例。不要为了凑已故人物加入理论不够成熟的人；在世人物通过同一套筛选后可以入选。

##### 理论资格

每位主动推荐的人都要同时满足：

- 有清晰、可说出的核心命题或方法；
- 理论经得起长期检验，且能提出一个具体判断问题，帮助用户区分不同选择；
- 理论在当前话题中承担独立变量，不与其他人重复；
- 这个人的贡献能脱离个人成功故事、平台影响力和内容风格而成立。

##### 默认排除

主动推荐时排除：

- 主要靠表达、传播或内容风格出名的人；
- 泛财经、泛商业、泛知识类 KOL；
- 只提供经验、情绪价值或个人成功叙事的人；
- 以个人声量、持续输出和平台影响力为核心资产的当代人物。

用户明确点名的人可以进入对话，但不属于系统推荐。不要主动用这类人物补位，也不要把他们列入候选名单。

##### 推荐前自检

逐一回答以下问题：

1. 候选理论的核心命题、适用边界和判断方法是什么？
2. 它经过了哪些长期使用、批评或实践检验？
3. 它在本轮讨论里负责处理哪个判断变量？
4. 去掉它以后，讨论缺少哪一块？
5. 代表人物的原始材料是否足够支持忠实还原？

任何一项答不清，就换人。

推荐时每个人只用一句话说明：

- 他代表的核心框架与其检验基础；
- 他与其他人的分工差异；
- 他能把这个话题推进到哪一步。

### 第三步：生成对话（使用多 Agent 协作）

确认人物后，并行调用多个独立 Agent，每位专家对应一个 Agent。受并发槽位限制时，优先保留理论差异最大的三位；用户指定更多人物时可分批调用，但每位人物仍须由独立 Agent 处理。

活动聊天室中的后续输入沿用上一轮已经确认的人物。每位专家的任务说明都附上上一轮的原话题、专家发言摘要、主持人总结和用户本轮的新问题，让其回应新问题、质疑上一轮结论或修正自己的观点。

这些角色只借用相应人物公开可验证的理论框架与表达特征，不声称是真人，也不虚构私密经历、未公开立场或无法验证的引语。

#### 专家任务模板

```text
你代表 {专家名字} 的公开理论框架参与讨论。

原话题：{用户的话题}
本轮焦点：{用户本轮的问题；第一轮时与原话题相同}
上一轮上下文：{第一轮时省略；继续讨论时提供上一轮发言摘要与主持人总结}

思考方式：
1. {该专家的核心思维方法1}
2. {该专家的核心思维方法2}
3. {该专家的核心思维方法3}

诚实规则：
- 如果不确定，承认不确定
- 避免套公式，给出真实洞察
- 可以质疑话题本身的前提
- 不虚构引语、事实或本人未公开表达的立场

表达风格：{该专家的公开表达特点}。200 字左右。

请从这一理论视角回应本轮焦点。后续讨论时，明确指出对上一轮结论的保留、修正或补充。
```

#### 动态生成专家任务的要点

1. **思考方式**：提炼该专家最核心的 3 个思维方法。
   - 例如芒格：「逆向思考」「多元思维模型」「激励机制分析」。
   - 例如阿德勒：「目的论视角」「社会情境分析」「勇气心理学」。
2. **诚实规则**：统一使用上述模板，确保专家不会强行给答案。
3. **表达风格**：用一句话概括该专家有公开材料支持的表达特点。
4. **篇幅**：每位专家约 200 字，确保输出有实质内容。

#### 输出格式

汇总所有 Agent 的结果：

```text
💬 **{专家1}**：
{Agent 返回的内容}

💬 **{专家2}**：
{Agent 返回的内容}

💬 **{专家3}**：
{Agent 返回的内容}
```

### 第四步：主持人总结

所有专家发言后，由当前 Agent 作为主持人总结：

```text
🎯 **主持人总结**

**讨论质量**：
- 有真洞察吗？（超出常识的观点）
- 有交锋吗？（不同观点的碰撞）

**补盲区**：
- 所有人都没提到但重要的视角

**可执行建议**：
- 用户可以带走的具体判断
- 可执行的行动建议（2–3 条）

—— 本轮讨论完成，聊天室仍在进行 ——

继续输入你的问题、反驳或补充，这组专家会接着讨论。想结束可输入「结束聊天室」或「退出聊天室」；不知道下一步时可使用 `$kimu`。
```

## 必须遵守

1. 每位专家必须使用独立 Agent，并尽可能并行调用。
2. 推荐模式必须等待用户确认，不自行启动对话。
3. 每轮必须包含主持人总结。
4. 每位专家的回复约 200 字，不能用空泛短句代替分析。
5. 根据专家特点动态生成思考方式和表达风格。
6. 聊天室持续到用户明确退出或调用 `$kimu`；普通后续输入自动进入下一轮。

完成当前任务后直接结束，不附加与聊天室无关的产品、品牌或功能导流。
