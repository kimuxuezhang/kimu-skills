# 案例库结构与证据规范

## 记录模板

每条案例使用以下字段，字段名保持不变：

```markdown
## KCB-Pxxx｜公共案例名称
## KCB-Uxxx｜私有案例名称

- 类型：教师实践 / 学员案例 / 课程产品 / 教培经营 / 内容与传播 / 公众案例 / 案例方向
- 优先级：1 / 2 / 3 / 4 / 5
- 适用主题：主题1；主题2；主题3
- 核心事实：
  - 只写来源能够支持的事实。
- 可用判断：
  - 说明案例可以支撑什么判断。
- 可用表达（非逐字引语）：
  - 可改写使用，但不得作为人物原话加引号。
- 提词稿压缩：
  - 1—3行，只保留理解该判断所需的事实。
- 来源：公开层使用公开链接或可定位出版物；私有层使用材料名、章节或时间戳，本地路径仅作辅助。
- 证据状态：已核对 / 可追溯 / 用户提供 / 待核对 / 案例方向
- 使用边界：数字、姓名、隐私、因果或适用场景限制。
- 搜索词：词1；词2；词3
```

## 存储层与编号

- 公开层位于技能包 `references/`，编号使用 `KCB-P001`、`KCB-P002`……
- 私有层默认位于 `~/.kimu/case-bank/`，编号使用 `KCB-U001`、`KCB-U002`……
- 公开层只能收录状态为 `已核对` 且不含未经授权敏感信息的案例。
- 用户材料默认进入私有层；未经用户明确同意，不得迁入公开层。
- 私有层不得复制到 GitHub 仓库、发布包或共享压缩文件。

## 证据状态

- `已核对`：已经回到原始材料定位到具体章节、页码、时间戳或可靠链接。
- `可追溯`：知道原始材料和大致章节，但首版尚未逐句复核。
- `用户提供`：事实由用户明确提供，可注明“据用户提供”，但不等于独立核实。
- `待核对`：只有线索或二手摘要，不得作为精确事实直接发布。
- `案例方向`：为了提示用户补素材而建立，不代表事件真实发生。

涉及数字、日期、人物原话、因果关系、学员结果时，即使记录为`可追溯`，最终发布前也要回源。公众案例使用时重新联网核实。

## 选择优先级

1. 用户授权读取、且直接证明当前判断的私有教师或学员案例
2. 可公开核验的教培、课程与知识付费案例
3. 可公开核验的内容、传播、商业或技术案例
4. 公众熟悉但与当前情境较远的可靠案例
5. 待补案例方向

优先级不是价值排名。相关性和证据质量高的案例优先，不因名人知名度或故事传播度提高等级。

## 收录边界

- 一个案例必须至少能支撑一个明确判断，不能只是故事梗概。
- 同一事件的不同版本优先合并；新事实写入原记录并补充来源。
- 不收录无法追溯来源的“听说”“网传”和名人金句。
- 不将生成式改写标记成原话。
- 涉及学员、未成年人、收入、疾病、家庭关系等信息时，默认匿名和最小披露。
- 观点提词稿只提取必要事实；完整案例保留在对应存储层，不复制到调用 Skill。

## 索引维护

`index.md`每条记录只保留：ID、名称、类型、适用主题、证据状态。新增或改名时同步更新；详情始终以`cases.md`为准。
