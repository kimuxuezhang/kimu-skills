# 案例库结构与证据规范

## 记录模板

每条案例使用以下字段，字段名保持不变：

```markdown
## KCB-xxx｜案例名称

- 类型：Kimu经历 / Nova业务 / 学员案例 / 教培与知识IP / 自媒体与AI / 公众案例 / 案例方向
- 优先级：1 / 2 / 3 / 4 / 5
- 适用主题：主题1；主题2；主题3
- 核心事实：
  - 只写来源能够支持的事实。
- 可用判断：
  - 说明案例可以支撑什么判断。
- 可用表达（非逐字引语）：
  - 可改写使用，但不得作为人物原话加引号。
- PPT压缩方向：
  - 1—3行，只保留理解该判断所需的事实。
- 来源：材料名、章节、时间戳或链接；本地路径仅作辅助。
- 证据状态：已核对 / 可追溯 / 用户提供 / 待核对 / 案例方向
- 使用边界：数字、姓名、隐私、因果或适用场景限制。
- 搜索词：词1；词2；词3
```

## 证据状态

- `已核对`：已经回到原始材料定位到具体章节、页码、时间戳或可靠链接。
- `可追溯`：知道原始材料和大致章节，但首版尚未逐句复核。
- `用户提供`：事实由用户明确提供，可注明“据用户提供”，但不等于独立核实。
- `待核对`：只有线索或二手摘要，不得作为精确事实直接发布。
- `案例方向`：为了提示用户补素材而建立，不代表事件真实发生。

涉及数字、日期、人物原话、因果关系、学员结果时，即使记录为`可追溯`，最终发布前也要回源。公众案例使用时重新联网核实。

## 优先级

1. Kimu真实经历、Nova业务或学员案例
2. 教培与知识IP案例
3. 自媒体与AI案例
4. 公众熟悉且可核实的案例
5. 待补案例方向

类型描述与优先级不必机械绑定。例如一个Kimu亲自参与的AI项目仍可列为优先级1。

## 收录边界

- 一个案例必须至少能支撑一个明确判断，不能只是故事梗概。
- 同一事件的不同版本优先合并；新事实写入原记录并补充来源。
- 不收录无法追溯来源的“听说”“网传”和名人金句。
- 不将生成式改写标记成原话。
- 涉及学员、未成年人、收入、疾病、家庭关系等信息时，默认匿名和最小披露。
- 课程PPT只提取必要事实；完整案例保留在本库，不复制到调用Skill。

## 索引维护

`index.md`每条记录只保留：ID、名称、类型、适用主题、证据状态。新增或改名时同步更新；详情始终以`cases.md`为准。
