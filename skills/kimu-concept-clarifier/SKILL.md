# Kimu 概念澄清

把模糊词语还原成当前问题中可观察、可比较、可使用的定义。目标不是寻找唯一字典答案，而是让用户知道自己究竟在判断什么。

用户可以输入：

```text
Kimu 概念澄清：{概念或原句}
```

## 先锁定语境

优先使用用户提供的原句、争议双方和现实决策。若一个词离开语境会产生多种合理解释，只问一个最能区分用法的问题，例如「你是在描述事实，还是在评价好坏？」

已有足够上下文时直接分析，不先做问卷。

## 澄清框架

### 1. 找出这个词正在完成什么任务

判断它在句子里主要用于：

- 指认对象；
- 描述机制；
- 划分类别；
- 评价好坏；
- 争取立场或推动行动。

同一个词同时承担多项任务时，先拆开再讨论。

### 2. 列出候选含义

最多保留三个与当前语境真正相关的含义。每个含义都写出：

- 它包含什么；
- 它排除什么；
- 用什么证据判断；
- 采用它会改变哪项结论。

不要用更多抽象词替换原来的抽象词。

### 3. 做边界测试

为主要定义构造三类例子：

- 明确属于；
- 明确不属于；
- 容易争议的边界情况。

如果定义无法稳定区分这三类，说明它仍不可用，需要缩小范围或补充判断条件。

### 4. 定位争议类型

区分问题究竟来自哪里：

- 双方使用了不同定义；
- 定义一致，但事实证据不同；
- 事实一致，但价值排序不同；
- 把相关性说成因果；
- 用群体标签代替对具体行为的判断。

不要把所有分歧都归因于“概念不清”。

### 5. 给出工作定义

工作定义必须服务于当前任务，格式为：

```text
在这次讨论中，“{概念}”暂时指：{对象或行为}在{条件}下表现出{可观察标准}。
它不包括：{最容易混入的相邻概念}。
```

若没有足够证据选定一个定义，保留两个版本，并明确各自会导向什么不同判断。

## 输出格式

```markdown
## 当前语境
{原句和实际要解决的问题}

## 含义分叉
1. {含义 A}：判断标准...
2. {含义 B}：判断标准...

## 真正的争议
{定义、事实、因果或价值中的哪一层}

## 边界测试
- 属于：...
- 不属于：...
- 边界情况：...

## 本轮工作定义
{可直接用于后续讨论的定义}

## 对原问题的影响
{定义澄清后，哪些问题消失了，哪些仍需证据}
```

简单概念可以压缩，不为凑格式制造内容。

## 可靠性边界

- 专业术语、法律定义、技术标准和时效性概念应核对权威来源。
- 词源可以提供背景，但不能替代当代语境中的实际用法。
- 不把某位思想家的可能看法写成未经核实的直接引语。
- 不替用户偷偷加入价值判断；需要规范性定义时明确说明。

完成澄清后停止。只有用户带来新语境或新证据时，才重新调整工作定义。
